# Детектор архитектуры исполняемых файлов

Определение архитектуры процессора для исполняемого файла с помощью **частотного анализа байтовых сигнатур** и машинного обучения — без необходимости полагаться только на парсинг заголовков (PE/ELF/Mach-O), который может не сработать на запакованных, обфусцированных или повреждённых бинарниках.

## Как это работает

Программа анализирует распределение частот байтовых паттернов в секции кода исполняемого файла, рассматривая это как сигнатуру набора инструкций процессора. Полученные частотные сигнатуры сравниваются с набором **заранее подготовленных эталонных сигнатур** (хранятся в папке `Signatures/`) с помощью трёх независимых классификаторов машинного обучения:

- **Random Forest**
- **K-Nearest Neighbors (KNN)**
- **Logistic Regression**

Каждая модель "голосует" за наиболее вероятную архитектуру, что даёт консенсусный прогноз вместо результата одной-единственной эвристики.

Такой подход особенно полезен, когда:
- Бинарный файл запакован или обфусцирован
- Стандартный парсинг секций (например, поиск секции `.text`/кода) не срабатывает
- Нужна независимая дополнительная проверка в дополнение к традиционному определению по заголовкам

## Возможности

- 🔍 Автоматическое определение архитектуры с помощью ансамбля ML-моделей
- 🧬 Анализ на основе частотных байтовых сигнатур (не полагается только на заголовки файла)
- 🛠 Продвинутый режим для ручного указания диапазона байт с ASM-инструкциями, если автоматический парсинг секций невозможен
- 📊 Встроенный инструмент для генерации собственных "эталонных" сигнатур
- 📝 Настраиваемый файл вывода и подробный (verbose) режим логирования

## Использование

```bash
python main.py <filename> [options]
```

### Позиционные аргументы

| Аргумент   | Описание                       |
|------------|------------------------------------|
| `filename` | Путь к анализируемому исполняемому файлу |

### Опции

| Флаг | Полная форма | Описание |
|------|-----------|-------------|
| `-d` | `--detect` | Попытаться определить архитектуру с помощью всех 3 ML-алгоритмов |
| `-a` | `--advanced` | Продвинутый режим — вручную указать диапазон байт, где расположены ASM-инструкции. Полезно, если файл запакован и секцию кода нельзя распарсить автоматически |
| | `--range` | Диапазон байт для анализа в продвинутом режиме (используется вместе с `-a`) |
| `-g` | `--gold` | Сгенерировать папку `Signatures/` с "эталонными" графами/сигнатурами для всех поддерживаемых архитектур |
| `-o` | `--output` | Файл для записи результатов (по умолчанию: `res.txt`) |
| `-v` | `--verbose` | Включить подробный вывод |

### Примеры

Автоматическое определение архитектуры:
```bash
python main.py sample.exe -d
```

Определение архитектуры с указанием файла вывода и подробным логированием:
```bash
python main.py sample.exe -d -o results.txt -v
```

Продвинутый режим — ручное указание диапазона байт для запакованного файла:
```bash
python main.py packed_sample.exe -a --range 0x1000 0x4000 -d
```

Пересоздать эталонные сигнатуры:
```bash
python main.py --gold
```
